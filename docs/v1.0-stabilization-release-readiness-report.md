## 4. Hydration Fix (P1)

### 4.1 Exact Root Cause
In Node.js 21+ and specifically Node.js v25.9.0 (the runtime executing this build):
- Web standard `globalThis.navigator` is defined in Node.js, so `typeof navigator !== 'undefined'` returns `true`.
- However, `navigator.onLine` is NOT implemented in Node.js and returns `undefined`.
- In `hooks/use-dashboard.ts`:
  ```typescript
  const [isOffline, setIsOffline] = useState<boolean>(
    typeof navigator !== 'undefined' ? !navigator.onLine : false
  );
  ```
  On the server: `!navigator.onLine` evaluated `!undefined` to `true`!
  Therefore, the server rendered the `<Alert className="...">Offline Authority Active</Alert>` banner.
- On the client (in browser): `navigator.onLine` is `true` (boolean). `!navigator.onLine` evaluated to `false`.
  The client rendered WITHOUT the alert banner, immediately showing the loading spinner.
- React detected the DOM node mismatch at line 268 of `dashboard-view.tsx` between the server's `<Alert>` and the client's `<div className="py-20 ...">`, triggering a hydration crash.

### 4.2 Implemented Fix
1. Initialized `isOffline` strictly to `false` on initial render across both SSR and client:
   ```typescript
   const [isOffline, setIsOffline] = useState<boolean>(false);
   ```
2. Added client-side synchronization inside `useEffect` (which runs only after hydration completes):
   ```typescript
   useEffect(() => {
     if (typeof window === 'undefined') return;
     if (typeof navigator !== 'undefined' && typeof navigator.onLine === 'boolean') {
       setIsOffline(!navigator.onLine);
     }
     const handleOnline = () => setIsOffline(false);
     const handleOffline = () => setIsOffline(true);
     window.addEventListener('online', handleOnline);
     window.addEventListener('offline', handleOffline);
     return () => {
       window.removeEventListener('online', handleOnline);
       window.removeEventListener('offline', handleOffline);
     };
   }, []);
   ```
3. Applied matching boolean guards in `hooks/use-sync-status.ts`, `lib/sync/sync-coordinator.ts`, and `contexts/workout-completion-context.tsx`.
4. Added unit test `tests/hydration-determinism.test.ts` to assert that Node.js SSR never outputs false offline alerts.
5. Verified live production SSR response (`Invoke-WebRequest http://localhost:3000/dashboard`): `Contains Offline Authority Active: False`.

## 9. Offline-First & Sync Robustness

1. **Guest Isolation**:
   - Verified that unauthenticated guest workouts remain strictly stored in local IndexedDB (`workout_planner_db`) and are dropped by `SyncOutbox.enqueue()` without attempting cloud sync.
2. **Authenticated Sync & Idempotency**:
   - When online connectivity resumes, `SyncCoordinator` replays mutations using deterministic idempotency keys (`${entityType}_${entityId}_${clientTimestamp}`), preventing duplicate rows in PostgreSQL.
3. **Service Worker Integrity**:
   - `public/sw.js` caches static application shell assets and routes (`/_next/static/`, `/icons/`, `/manifest.webmanifest`).
   - Explicitly bypasses all Supabase authentication, token exchanges, and sync endpoints.
   - Cache eviction listeners never touch or purge IndexedDB databases.
